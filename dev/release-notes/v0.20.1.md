## v0.20.1 — 装不上的三种情形，这次一起修了

一晚上连着三条反馈，都是「明明该能装，面板却停在半路」。三条根因各不相同，
共同点是：**是面板做得不够，不是用户操作有问题**。

### ① 选错了安装包（Release 里有两个资产）
`woniuniuniu/dsh-media-desk` 的 Release 同时有 `…-with-install-guide.zip`
（安装说明 + 内层包）和 `…2.6.1.tgz`（真正的插件包）。旧规则只看「名字里有没有 dsh」，
两个都命中 → 拿了 GitHub 返回的第一个 —— 套壳 zip。解出来既没有 `dsh.bundle`
也没有 `SKILL.md`，于是判「未识别」，预检阻断。

现在按「最可能是插件包」**排序**：`.tgz` 优先，`with-install-guide` / `说明` / `setup` /
平台二进制一律降权；落选的资产不会浪费，作为 `alternatives` 记在任务上。

### ② 卡在「已转人工确认」，没有下一步
阻断之后只有「重新诊断 / 重试」，而错误文案却写着「看面板里的『下一步』」——
那句话此前**没有对应的界面**。

现在阻断的任务多一张**「下一步」**卡：
- 同版本还有别的资产 → 直接给「改用 `xxx.tgz`」按钮，一次点击重试；
- 没有候选 → 说清「把解压后的插件目录拖进来 / 贴本地路径」；
- 顺带说明「包里还有一个归档：xxx，那个才像插件包」。

### ③ 路径过长，打不进 tgz
装带深层素材的插件（`skills/…/assets/screenshot-backgrounds/style-b/….webp`）时报
「路径过长，无法打进 tgz」。根因是**手写的 ustar 只写了 100 字节的 `name`**，超长就拒绝 ——
而标准本来还有 `prefix`（155 字节）和 PAX，**读端早就支持，只有写端没实现**。

现在：能拆的走 ustar `prefix`，更长的走 PAX 扩展头；打包路径越界检查照旧保留。
