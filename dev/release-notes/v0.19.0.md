## v0.19.0 — 回滚不吃手改 / 本地改动可导出 / 第十步重启 / 跨写法去重

B 站评论区的四条反馈 + 一个追问（「装之前手改过 cordis.patch.yml，回滚会不会一起吃掉？」），逐条落到代码里。

### 1. 快照补全 + 回滚改成三方比对
- `pnpm-workspace.yaml` 进快照 —— R31 的 `trustPolicyExclude` 正写在它里面，以前回滚会漏掉这一条。
- 装完之后再拍一份 `post`；回滚按 `pre / post / now` 判：
  `unchanged / restore / remove / conflict / added / unverified`。
- **装完之后你手改过的 `cordis.patch.yml` 不会被覆盖**：当前内容另存到 `<快照>/conflicts/*.bak`，
  并在回滚结果里点名报出来（含 +/− 行数与第一处不同）。
- 这次安装**新建**的配置（例如 MCP 追加出来的 patch 文件）回滚时**删掉**，才算回滚干净。
- 旧快照没有 `post` → 先备份当前内容再还原，并如实说明「这份判断没有依据」。

### 2.「改过不覆盖」配上了 patch 导出
- 覆盖本地改过的 Skill 之前，先把「你的改动 vs 上游新版」导成 `data/patches/<name>-<时间>.diff`
  （行级 LCS 统一 diff；二进制与超大文件如实跳过，不编造）。
- 没有差异**不写空文件**；导出失败**不影响安装**（只是少一份证据）。
- 面板备注里给出路径与 +/− 行数，装完新版可照着重放 —— 不再二选一。

### 3. 第十步 · 重启 DSH 才生效
- 新增纯函数 `restartPlan(job)`：**按改动落在哪一层**判，不按宿主回执。
  插件 / 换版本 / MCP → 要重启；技能落目录 → 不要（宿主会重扫）；宿主说 `restart-required` → 兜底也算。
- 诊断里固定一条 `code: "restart-step"`，写清那个真实场景：模块加载时就固化的路径 / 环境变量，
  文件放好了、诊断也过了，**进程里还是老值**。

### 4. 跨写法去重
- 新增 `dedupeKeyOf()`：`github:o/r`、`https://github.com/o/r`、带尾斜杠、`.git`、大小写 →
  折算成同一个键；**ref 与子目录不同仍是不同键**（不瞎并）。
- 新增 `findActiveDuplicate()`：同名同类的第二条任务直接拒绝（`duplicate-active`），
  两条任务不再一起往同一个包名上写。
