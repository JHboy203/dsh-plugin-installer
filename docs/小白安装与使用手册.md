# DSH 插件安装面板 · 小白使用手册

适用于 **dsh-plugin-installer v0.19.x**（当前 `0.19.1`，2026-11）

这份手册是写给「完全没接触过编程」的人看的。它不要求你懂命令、懂代码。
遇到看不懂的词，直接翻到最后一节「名词小抄」。

如果你只想快点装完，看 **第 0 节** 和 **第 3 节** 就够了。
如果装出问题了，直接跳到 **第 9 节**（怎么把报错发出去，那才是最快的解决办法）。


## 0. 三十秒速览

- 这是什么：给 DSH 装插件用的「应用商店式面板」。
- 装它要几步：双击一个 exe → 看到「安装完成」→ 完全退出 DSH 再打开。**三步**。
- 装完在哪：DSH 左侧栏会多一个「插件安装」图标（方块里带一个向下箭头）。
- 出问题发什么：双击 `03 出问题\收集报错信息（双击）.cmd`，桌面会生成一个 txt，把那个 txt 发出来就行。**不要手打报错文字、不要只发截图**。
- 想细看：双击 `02 使用手册（浏览器打开）.html`（用浏览器看，不挑机器）；装了 Word 就看 `.docx`。


## 1. 它是什么？装它有什么用？

DSH（DeepSeek Harness）本身是个空壳：真正干活的能力大多来自「插件」。
以前装插件要会敲命令、要认得「profile 目录」「link 依赖」这些词，一步错就装不上。

这个插件就是把这件事变成**点几下**：

- **装插件**：把 GitHub 链接、下载页地址、`.zip` / `.tgz` 文件，甚至本机的文件夹，丢进面板的输入框（也可以直接把文件拖进去），它自己完成：
  下载 → 解包 → 认出这是什么 → 安全检查 → 备份 → 安装 → 自检（装坏了还能回滚）。
- **找插件**：面板里有搜索，可以从 npm（包仓库）、GitHub、第三方插件商店一起找；
  每条结果会带「官方 / 有源码 / 许可证 / 更新活跃度 / 下载量」这类判断，方便你看它靠不靠谱。
- **让 AI 推荐**：一句话描述你想要什么（例如「给对话加折叠」「视频下载」），它给你几条候选，你点「安装这个」就装。
- **检查更新**：一次点完，插件、MCP、Skill 三类一起查，能看出「该不该升」。
- **装 Skill / MCP**：Skill 是「技能文件」（教 AI 怎么做某件事），MCP 是「外部工具服务」，这个面板都能装。
- **环境体检**：任意页面按 `Ctrl+Alt+D`，它自检一遍，直接告诉你「现在重启安不安全」。

**关键一点：安装这个动作本身不花 AI 的钱（0 token）。**
确定性的事情（下载、解包、检查、安装）都是本地代码干的，AI 只负责「推荐」和「装完后的语义审查」。


## 2. 装之前，先确认三件事

1. **系统是 Windows 10 或 Windows 11。** 这个安装包只支持 Windows。
2. **DSH 已经装好、能正常打开。** 这个面板是给 DSH 用的，DSH 都没有就没法装。
3. **DSH 的版本是 0.2.x（0.2.1 或更新）。**
   你不用自己去翻版本号——**安装器第 1 步之后就会读出你的 DSH 版本并当场告诉你合不合格**：
   - 合格：它会打一行绿色的「DSH 版本在支持区间内」。
   - 太老（0.1.x）：它会红字停下来说「DSH 版本太老」，让你**先升级 DSH** 再装。
     （老版本不认新插件的加载方式，装上也不会出现在侧栏，白折腾。）
   - 也可以自己确认：打开 DSH 的「设置」，找「关于 / 版本」，看到 `0.2.1`、`0.2.2` 这样的就行。

顺便说清三件「不需要」的事，省得你多装东西：

- **不需要管理员权限**（不需要「以管理员身份运行」，也不弹 UAC）。
- **不需要装 Node.js、npm、pnpm**。DSH 自己带运行环境。
- **不需要关杀毒软件**。只有 Windows 自带的「SmartScreen」可能拦一下（见 3.1 第 3 步）。


## 3. 安装：三种方式，任选一种

> 三种方式装出来的结果**完全一样**。选一种就好，不用都做。
> 推荐「方式一」，它最省事；方式一被拦住时用「方式二」。

### 3.1 方式一：双击安装包（推荐）

1. 把下载到的压缩包**解压到桌面**（或者任意一个你能找到的文件夹）。
   - 不要在压缩软件的预览窗口里直接双击，那样会失败。
2. 进入解压出来的文件夹，双击 **`01 安装（双击这个）.exe`**。
3. 如果弹出蓝色窗口说「Windows 已保护你的电脑」（SmartScreen）：
   - 点左边的 **「更多信息」**；
   - 然后点右下角的 **「仍要运行」**。
   - 为什么会有这个提示：这个 exe 没有花钱买数字签名证书，属于「没见过的程序」的正常提示，不代表有毒。
4. 会出现一个黑色窗口，接着弹出第二个窗口（蓝底或黑底），一行一行往下走：
   - `>> 查找 DSH profile`
   - `>> 部署插件文件`
   - `>> 接线（node_modules 目录联接）`
   - `>> 登记到 profile`
   - `>> 已知坑检查`
   - 最后是绿色的 **「安装完成！」**
5. 如果它说找不到 profile，会弹出一个「选择文件夹」的对话框：**选你的 DSH 工作区目录**。
   特征：那个文件夹里面能看到一个叫 `.dsh` 的文件夹（前面带点的，可能看不见，那就在「查看」里打开「显示隐藏项目」）。
   一般是你平时放 DSH 文件的地方，例如 `D:\信息库\AI工作区`。
6. 最后会提示 **「按回车关闭」**，按一下回车。
7. **完全退出 DSH，再重新打开。**
   - 只点右上角 × 不算退出：DSH 会缩到右下角托盘继续跑。
   - 正确做法：右下角托盘图标上右键 → 退出；或者用任务管理器结束 `DeepSeek Harness`。
   - **不做这一步，你是看不到新面板的**（插件在 DSH 启动时才加载）。

### 3.2 方式二：解压后双击 `install.cmd`（方式一被拦、或窗口一闪而过时用）

1. 解压安装包。
2. 进到 `04 备用安装方式` 文件夹，**先解压** `dsh-plugin-installer-<版本>-portable.zip`（右键 → 全部解压缩）。
3. 打开解压出来的文件夹，双击 **`install.cmd`**。
4. 其余步骤和方式一第 4～7 步完全一样。

为什么留这一条：有些电脑上安全软件会直接把 exe 拦掉（双击毫无反应），
而 `.cmd` + 解压出来的脚本通常不受影响，而且窗口不会一闪就没，报错看得见。

### 3.3 方式三：直接把包拖给 AI 装

如果你的 DSH 已经能用 AI 干活，也可以偷懒：

1. 把 `04 备用安装方式\dsh-plugin-installer-<版本>.tgz` **拖进 DSH 的对话输入框**。
2. 说一句：「帮我装这个插件。装完告诉我怎么重启验证。」
3. AI 会读包里的 `交给AI安装.md`，按里面的步骤做（包括「不要用 pnpm」「装完要完全重启」这些坑）。
4. 装完它一般会提醒你**完全退出 DSH 再打开**，照做即可。

注意：让 AI 装时，**不要**让它顺手「升级/重装别的插件」——
那会触发 pnpm，而 pnpm 在这件事上很容易把环境弄坏（见第 7 节）。

### 3.4 安装器每一步在干什么（对照着看，知道它没卡住）

它依次会做这几件事（每一步都会打印出来，你可以对照着看它走到哪了）：

- **`查找 DSH profile`** —— 找到你 DSH 的「配置文件夹」（所有插件都登记在这里）。
- **`部署插件文件`** —— 把插件文件拷进去；如果以前装过，旧的那份会自动改名留底（`.bak-时间`）。
- **`接线（node_modules 目录联接）`** —— 建一个「快捷方式」，让 DSH 能找到这份插件（是链接，不是复制）。
- **`登记到 profile`** —— 在配置文件里写两行：这个插件叫什么、要不要启动时加载。
- **`运行环境体检`** —— 看这个插件还需要什么额外环境（本插件不需要，几秒就过）。
- **`已知坑检查`** —— 检查你机器上有没有「会让插件全挂」的老问题（例如 dsh-tools 覆盖）。
- **`安装完成！`** —— 好了，剩下的就是重启 DSH。

它一共只会改这几个地方，**每一处都能回退**：

```
<你的 DSH 工作区>\.dsh\profiles\desktop\dsh-plugins\dsh-plugin-installer\   插件文件本体
<你的 DSH 工作区>\.dsh\profiles\desktop\node_modules\dsh-plugin-installer    目录联接（快捷方式）
<你的 DSH 工作区>\.dsh\profiles\desktop\package.json                         加两行登记（改之前自动备份）
<你的 DSH 工作区>\.dsh\profiles\desktop\dsh-plugins\backups\                 每次修改前的备份
```

### 3.5 安装结束的三种结果

- **绿色「安装完成！」**：成功了。按回车关闭窗口，然后完全重启 DSH。
- **黄色提示「已经装过了」**：以前用别的方式装过这个插件，安装器不会覆盖你现在的版本，直接重启 DSH 就能用。
- **红色「DSH 版本太老」**：你的 DSH 还是 0.1.x。**这一步它什么都没改**，先升级 DSH，再跑一次安装包。
- **红色「安装未完成」**：某一步失败了。窗口里的红字会说是哪一步；**别自己修**，按第 9 节收集报错发出来。


## 4. 装完之后：确认它真的起来了

很多人卡在这一步：「装好了啊，什么都没变」。按下面三步验证：

1. **完全退出 DSH，再打开。**（再强调一次：托盘里的也要退）
2. 看左侧栏：应该多了一个 **「插件安装」** 图标（方块里一个向下箭头），排在其它面板图标之间。
3. 点它 → 右边整片会变成「插件 / Skill 安装」面板，标题旁边有版本号（例如 `0.19.1`）。

再补一条「一眼就知道环境好不好」的办法：**在任意页面按 `Ctrl+Alt+D`**，
右下角会浮出一个小窗，几秒后给你一句话结论，例如「环境正常，没有埋雷」。
如果它说「清掉了 N 项 —— 现在重启是安全的」，就照它说的重启一次。

**还是找不到图标？** 按顺序排查：

- 是不是**只关了窗口没真退出**？打开任务管理器看还有没有 `DeepSeek Harness` 在跑。
- 打开 DSH 的「设置 → 插件」，搜 `dsh-plugin-installer`，看它是不是「已启用」。是「已禁用」就打开它，再重启一次。
- 还是不行 → 第 9 节，收集报错发出来。


## 5. 第一次打开面板：那个「AI 模型」的弹窗请看完

装好后第一次点开面板，会先弹一个说明框。**别急着关**，它讲的是这件事：

这个面板里有三处会用到 AI，都要花钱（走你自己的模型额度）：

1. **装完之后的语义审查**：装完一个插件，它会用 AI 看一眼代码有没有可疑行为（异步的，不挡你安装；判成可疑会标红并建议回滚）。
2. **AI 推荐**：你描述需求、它给候选。
3. **AI 辅助添加搜索来源**（可选功能）／网页来源解析（**默认关闭**）。

然后它会告诉你三件事：

- **现在用的是哪个模型**：默认「跟随 DSH 设置里的默认模型」。
- **材料会发给谁**：审查时最多约 1.2 万字的代码片段会发给你选的那个模型服务商。所以**别用免费中继做安全审查**。
- **两条路**：`去选一个模型`（立刻挑一个）/ `先用默认`（以后再说）。

之后随时可以改：面板右上角 **设置 → AI 模型**，里面还有 **「再看一次引导」**，想重看就点它。

> 一句话建议：不知道怎么选，就先用默认；等哪天发现「AI 推荐」不好用了，再回来换成你自己的强模型。


## 6. 日常怎么用（六个最常用操作）

### 6.1 装一个插件（最常用）

1. 在浏览器里找到插件主页，**复制地址**（GitHub 仓库页、Release 页、npm 包名都行）。
2. 回到面板，粘到最上面的输入框里（提示文字写着「GitHub 链接 / Release 页 / .tgz·.zip 直链 / …」）。
   - 也可以**直接把文件拖进这个输入框**（本机 `.zip` / `.tgz` 都行）。
   - 想装 MCP 服务器，就写 `mcp:<它在 Registry 里的名字>`。
3. 按回车（或点旁边的提交按钮）。
4. 下面会出现一条任务，一行行走：下载 → 解包 → 识别 → 预检 → 快照 → 安装 → 诊断。
5. 如果有风险，它会停在 **「等待确认」**，把「它要什么权限」「和用途对不对得上」列给你看。看懂了就点 **「确认安装」**。
6. 完成后再看面板上那一行的结论；需要重启的，它会提示你。

### 6.2 搜插件、让 AI 推荐

- **搜**：在输入框里打关键词（`pdf`、`截图`、`表格`…）回车。结果带可信度徽章，点 **「安装这个」**。
- **推荐**：下面「AI 推荐」那个框里说人话，例如「给对话加折叠」「视频下载」「做个 ppt」，点提交。
  它给 1～3 条（可在 设置 → AI 推荐 里调），每条都能一键装。
- 它会自动覆盖三类：插件、Skill、MCP。Skill 的按钮叫 **「安装这个 Skill」**。

### 6.3 检查更新

面板中间有一条 **「插件 / MCP / Skill 更新」**，点 **「检查更新」**：

- 30 分钟内查过就直接给结果（不重复联网）。
- 只能查「有版本来源」的：npm 上架的、有登记来源的 Skill。本机目录装的、手工塞进去的，会如实写「无法判断」——**这不等于坏了**。
- 想升级，点 **「全部升级 N」** 或单条升级。有些包会要求「先卸载旧版再装」，面板会告诉你这一步。

### 6.4 看装了些什么

点右上角 **「清单」** → 已装插件 / 已装 Skill / 已装 MCP。
每个条目能看到：版本、来源（npm / 本机链接 / 压缩包）、有没有更新、报不报错。

### 6.5 卸掉一个插件

清单 → 已装插件 → 对应条目 → 卸载。卸完**完全重启 DSH** 才生效。

### 6.6 环境体检 / 一键修复

任意页面按 `Ctrl+Alt+D`。它会检查那些「会让插件集体失灵」的老毛病，能自动修的会问你修不修。
快捷键被别的软件占了（有些输入法会抢 `Ctrl+Alt+字母`），可以在 **设置 → 自检快捷键** 里换一个或关掉。


## 7. 必须知道的 10 条注意事项

1. **装完必须「完全退出」再打开 DSH。** 只关窗口 = 没退出（它会缩到托盘）。插件是启动那一刻加载的，热重载对它无效。
2. **别点恢复对话框里的「禁用第三方插件」按钮。** 一旦点了，DSH 会把你所有插件的登记清单从几十项裁到 2 项——等于把别人的劳动一刀砍掉，还得手动恢复。真起不来时，先按第 9 节收集报错，再交给 AI 或作者看。
3. **不要用 `pnpm` / `npm` 给 DSH 装插件。** 这样装会在你的 profile 里多塞一份 `@deepseek-ai/dsh-tools`，之后**每一个工具都会报 `prepare undefined`**，看起来像整个 DSH 坏了。这个面板的「直连安装」就是为此存在的：它不碰 pnpm。
4. **安装执行不花钱，AI 功能花钱。** 装一个插件本身 0 token；但「AI 推荐」「装完的语义审查」「网页来源解析」会消耗你选的模型额度。
5. **这是开发版，界面会变。** 面板右上角的版本号（现在是 `0.19.x`，具体以面板显示为准）才是权威；功能位置以后可能挪动，找不到就先看「设置」和「清单」两个入口。
6. **自定义搜索来源 = 只是渠道，不背书。** 面板只负责帮你连上去；插件代码安不安全、好不好用，要你自己判断。自定义来源的命中会标「未验证」。它只接受公网 `http(s)` 地址，本机 / 内网 / 带账号密码的地址会被拒绝（这是有意为之的安全边界）。
7. **装插件时不要在多个地方同时装同一个。** 例如面板里点了一次、又让 AI 装一次：两条任务会抢同一个目标目录。等一条跑完再动。
8. **装完一个插件就重启一次，别一口气装十个再重启。** 万一其中哪个有问题，你分不清是哪个。装完随手按一下 `Ctrl+Alt+D` 更稳。
9. **磁盘上会留备份和快照，占空间可以清。** 位置在 `<profile>\dsh-plugins\dsh-plugin-installer\data\` 下的 `snapshots`（安装前快照）、`staging`（下载解包临时区）、`patches`（覆盖技能前导出的本地改动）。面板里也有「清理历史」。
10. **「回滚」不会吃掉你装完之后的手改。** 回滚按文件比对「装之前 / 这次安装写的 / 现在」三份内容：装完之后你自己改过的文件（比如又往 `cordis.patch.yml` 里加了一条 MCP），回滚**不会覆盖它**，而是把当前内容另存一份，并在结果里点名说「这一处我没动」。详见 Q20。
11. **改过的技能升级时会先导出你的改动。** 重装一个本地改过的 Skill 时，覆盖之前会先把你改的内容导成 `data\patches\<技能名>-<时间>.diff`，装完新版照它重放即可 —— 不用再在「保住改动」和「升级」之间二选一。详见 Q21。
12. **看到「第十步 · 重启 DSH 才生效」就去重启。** 那不是报错，是提醒：插件 / 换版本 / MCP 都只在启动时加载。详见 Q22。
13. **出问题的第一反应是「收集报错」，不是「重装一遍」。** 重装会覆盖现场，把最值钱的证据弄丢（见第 9 节）。


## 8. 常见问题（按症状查）

> 每一步都是「症状 → 为什么 → 怎么办」。看不懂就直接按第 9 节把报错发出来，别硬修。

**Q1：双击 exe 之后，黑色窗口一闪就没了。**
- 原因：多数是被安全软件拦下，或者系统不允许在这个位置运行。
- 怎么办：改用第 3.2 节的「方式二」（解压后双击 `install.cmd`），窗口会停住，报错能看清。

**Q2：弹「Windows 已保护你的电脑」。**
- 原因：exe 没有数字签名，系统对「不认识的程序」的默认提示。
- 怎么办：点「更多信息」→「仍要运行」。这是正常流程，不是病毒。

**Q3：安装器说「自动没找到 DSH profile」。**
- 原因：你的 DSH 工作区不在常见位置，它自己猜不到。
- 怎么办：在弹出的「选择文件夹」里选你的 DSH 工作区（里面有个 `.dsh` 文件夹的那个）。选完它会继续。
- 还是找不到：打开 DSH 的「设置」，看它显示的工作区/数据目录在哪，然后选它的上一级。

**Q4：装完了，但左侧栏没有「插件安装」图标。**
- 原因 1（最常见）：**没有真的退出 DSH**，只是关了窗口。
- 原因 2：DSH 版本太老（0.1.x），这个面板加载不了。
- 怎么办：任务管理器里结束 `DeepSeek Harness` 再打开；仍然没有 → 「设置 → 插件」里搜 `dsh-plugin-installer` 看是否被禁用；都不行 → 第 9 节。

**Q5：图标在，点开是一片空白 / 一直「加载中」。**
- 原因：面板在等后端的数据，但后端还没准备好（常见于刚装完没重启、或者宿主里有个插件加载失败了）。
- 怎么办：完全重启 DSH 一次。还是空白 → 打开面板前先按 `Ctrl+Alt+D` 看自检结论，然后按第 9 节收集。

**Q6：面板打不开，浏览器控制台或提示里出现「不是 JSON（HTTP 404）」。**
- 原因：这个插件的后端没起来（通常是「别的插件加载失败，连累了整棵树」），不是面板坏了。
- 怎么办：`Ctrl+Alt+D` 自检并修复 → 重启；或按第 9 节收集，让 AI 看「上一次启动失败」日志。

**Q7：重启之后，一大批插件都不见了 / 工具全报错，提示里有 `prepare` 或 `reading 'prepare'`。**
- 原因：profile 里被塞了一份多余的 `@deepseek-ai/dsh-tools`（多半是某次 pnpm 装插件留下的）。它会把宿主自带的那份顶掉。
- 怎么办：这是已知老毛病，有现成修法——让 AI 跑工作区里的修复脚本（`.tools\dsh_doctor.py --fix`）或插件的自检修复；修完重启。**不要点**恢复对话框里的「禁用第三方插件」。

**Q8：安装停在「等待确认」，一直不动。**
- 原因：预检发现了风险（可能要跑安装脚本、可能权限过大），在等你说「我知道了」。
- 怎么办：看卡片里列的理由，判断你信不信这个插件；信就点「确认安装」，不信就点取消/清理历史。不点它就一直等着。

**Q9：安装失败，红字里有 `ERR_PNPM_TRUST_DOWNGRADE`。**
- 原因：**不是你要装的那个插件的问题**，是你 profile 里某个「别的包」没有可信发布记录，pnpm 把这整次安装拒了。
- 怎么办：面板会给出两条出路：①「豁免这一个版本」（会先备份再写）；② 本机目录类插件用「直连安装（不走 pnpm）」。按提示点就行。

**Q10：安装失败，红字里有 `ERR_PNPM_RESOLUTION_POLICY_VIOLATIONS`。**
- 原因：同上，pnpm 的策略门在拦「整次安装」，跟你这个插件无关。
- 怎么办：优先换「直连安装」这条路；或者把报错发出来（这类要动 profile 的 lock 文件，别自己手改）。

**Q11：DSH 起不来了 / 一开就进「恢复」界面。**
- 怎么办：先**不要**点「禁用第三方插件并重启」。按 `Ctrl+Alt+D` 自检（如果还能按到），或让 AI 跑修复脚本；同时按第 9 节收集报错。最坏情况下用 profile 的备份恢复（安装器每次改配置前都留了备份，在 `dsh-plugins\backups\`）。

**Q12：AI 推荐报「本机没有设置默认模型」。**
- 原因：DSH 里没设置默认模型，面板也没自选。
- 怎么办：DSH「设置 → 模型」里选一个默认；或面板「设置 → AI 模型」里自选一个。

**Q13：搜索没结果 / 自定义来源一直失败。**
- 原因：网络（npm / GitHub 在国内可能不稳）、或者那个来源本身挂了。
- 怎么办：先只留内置来源试一次；换关键词；过几分钟再试。自定义来源失败只标它自己，不会影响别的来源。

**Q14：检查更新全是「无法判断」。**
- 原因：这些插件不是从 npm 装的（比如本机目录、压缩包），本来就没有版本源可比。
- 怎么办：这不是故障。想升级就重新装一次新版本。

**Q15：升级时提示「要先卸载旧版」。**
- 原因：同一个包名不能同时存在两个版本，面板要求先请「插件目录」把旧的卸掉。
- 怎么办：按提示走（它会分两段：先卸载、再安装）。中途断了可以续跑。

**Q16：面板用起来有点卡。**
- 原因：装了很多插件，面板一次要读很多清单 / 历史。
- 怎么办：清单里的「清理历史」清掉已结束的记录；少开几个面板页；关掉不用的插件。

**Q17：卸载了插件，图标还在。**
- 原因：没重启（宿主还拿着旧的内存状态）。
- 怎么办：完全退出 DSH 再打开。

**Q18：中文显示成乱码 / 方框。**
- 原因：系统的代码页或字体问题（安装器已经强制用 UTF-8 处理）。
- 怎么办：把系统区域设置里的「Beta: 使用 Unicode UTF-8 提供全球语言支持」保持默认；还乱码就把报错 txt 发出来（txt 里是 UTF-8，能正常看）。

**Q19：面板里装某个压缩包，报「本机解不开这个格式」或「bsdtar 解不开」。**
- 原因：`.zip` / `.tar` / `.tar.gz` 是面板自己解的，不挑机器；但 **`.7z`、`.rar`、以及超大（zip64）包**要靠 Windows 自带的 `tar.exe` 来解，这个工具从 Windows 10 1803 起才有。
- 怎么办：① 用 7-Zip 之类的解压软件把它**转成普通 `.zip`** 再装（最稳）；② 或者升级 Windows；③ 加密压缩包请先解密再装。

**Q20：点「回滚到安装前」，会不会把我装完之后自己改的 `cordis.patch.yml` 也一起改掉？**
- 不会（0.19.0 起）。回滚是**按文件三方比对**：装之前的样子、这次安装写下的样子、现在磁盘上的样子。
  - 现在 = 这次安装写的 → 还原成装之前；
  - 现在既不是装之前也不是这次安装写的 → 说明**装完之后你手改过**，回滚**不覆盖**，
    而是把当前内容另存到 `<profile>\dsh-plugins\dsh-plugin-installer\data\snapshots\<快照>\conflicts\`，
    并在回滚结果里写「有 N 个文件装完之后被改过，没有覆盖」。
- 顺带两件事：这次安装**新建**的配置（例如 MCP 追加出来的 patch 文件）回滚时会被删掉，才算干净；
  很老的快照（0.19.0 之前拍的）没有「装完之后」那份记录，回滚会**先备份当前内容再还原**，并说明「这份判断没有依据」。

**Q21：我改过某个技能，还想升级到上游新版，怎么办？**
- 直接点「按来源重装」就行。它第一次会拦一下（提示你本地改过），确认后**覆盖之前会先把你的改动导成 patch**：
  `data\patches\<技能名>-<时间>.diff`，面板备注里能看到路径与 +/- 行数。
- 装完新版后照那份 diff 把你的 `+` 行抄回对应文件即可（有 git 的话 `git apply` 也行）。
- 一句话：现在不用再在「保住我的改动」和「拿到上游更新」之间二选一。

**Q22：诊断里出现「第十步 · 重启 DSH 才生效」，是出错了吗？**
- 不是。它是一句提醒：插件、换版本、MCP 配置都是**启动那一刻**才读的，文件放好了、诊断也过了，
  进程里可能还是老值（尤其是那些在模块加载时就读路径/环境变量的插件，比如 ffmpeg 路径）。
- 怎么办：完全退出 DSH（托盘右键退出）再打开，然后点「重新诊断」，这条消失就说明已经生效。
- 技能（Skill）落目录不需要重启 —— 所以那条提醒只会在插件 / 换版本 / MCP 之后出现。


## 9. 出问题了，怎么把报错发给我（重要）

**请把「报错」当成一个文件来发，不要手打、不要只截图。**
手打的报错十次有八次是错的（漏字、大小写、路径少一层），截图里的小字也经常认错，
这会让本来 5 分钟能解决的事拖成一小时。

### 9.1 一键收集（推荐，最简单）

1. 打开安装包解压出来的文件夹，进入 **`03 出问题`**。
2. 双击 **`收集报错信息（双击）.cmd`**。
3. 等 10～30 秒（它会自己跑一些检查，屏幕上会滚动几行）。
4. 桌面上会多出一个文件：**`DSH插件安装-报错信息-年-月-日-时-分.txt`**。
5. **把这个 txt 发出来**：
   - 发给 AI：直接把文件拖进 DSH 的对话框，再说一句「帮我看看这个报错」。
   - 发给作者：把这个 txt 传过去就行。

这个 txt 里装了什么（所以大部分问题看一眼就够定位）：

- 你的 Windows 版本、计算机名、用户名（只有名字，没有密码）。
- DSH 装在哪、版本号、profile 路径、当前装了哪些插件（只有名字和版本，**没有对话内容**）。
- 这个插件的安装日志（桌面上的 `dsh-plugin-installer-安装日志.txt` 全文）。
- 当前面板/插件的运行状态（有没有加载失败、有没有 dsh-tools 覆盖这类「会让插件全挂」的坑）。
- 常见日志的最后几十行（里面**可能有你自己的提问片段**，发之前你可以先打开扫一眼，觉得敏感就自己删掉那几行——其他内容请别删）。

> 这个收集脚本是**只读**的：它只读信息、只写那一个 txt 到桌面，不改你的任何配置、不联网、不需要管理员。

### 9.2 顺手把这两句话也说清楚

收集的文件只能说明「机器是什么状态」。要让问题更快解决，再补两句人话：

1. **我想做什么**：例如「我想装一个截图插件」。
2. **我看到了什么**：例如「点安装以后，一直停在『等待确认』，我点了确认也没动」。

### 9.3 桌面上的安装日志

安装器每次运行都会在桌面写一份 `dsh-plugin-installer-安装日志.txt`（覆盖上一份）。
它是「安装那一次」的流水账，第 9.1 节的收集脚本会把它一起打包进去，所以你一般不用单独发它。

### 9.4 别做的三件事

- 别为了「让它干净」而把插件目录删掉再重装——那会把现场抹掉。
- 别点恢复界面的「禁用第三方插件」——见第 7 节第 2 条。
- 别自己改 `package.json`（尤其别用记事本另存为，容易把编码搞坏，DSH 会直接读不出来）。


## 10. 卸载 / 后悔了怎么办

**方法一（推荐）**：安装包里带了一个卸载脚本。

1. 解压安装包，进 `04 备用安装方式`，把 `portable.zip` 解压出来。
2. 双击 **`uninstall.cmd`**。
3. 完全退出 DSH 再打开。

**方法二（彻底删）**：在上面基础上，用命令行把插件文件一起删（会丢设置与历史）：

```
powershell -ExecutionPolicy Bypass -File install.ps1 -Uninstall -Purge
```

（在解压出来的那个文件夹里，按住 Shift 右键 →「在此处打开 PowerShell 窗口」，再粘贴上面这行。）

**注意**：卸载只解除「登记 + 链接」，你的 DSH 本身、别的插件都不受影响。
卸载后如果 DSH 行为异常，先完全重启一次再说。


## 11. 名词小抄

- **DSH / DeepSeek Harness**：你正在用的这个软件本体（宿主）。
- **插件 / plugin**：给 DSH 加功能的包。
- **Skill / 技能**：一份「教 AI 怎么做事」的说明文件（通常是一个文件夹里放一个 `SKILL.md`），不做界面。
- **MCP**：一种「外部工具服务」的接入标准，装上之后 AI 能调用那个服务提供的工具。
- **profile**：DSH 的「配置档案」文件夹，所有插件都登记在它下面的 `package.json` 里。默认叫 `desktop`。
- **宿主 / 客户端**：宿主 = 后台那半（跑插件、跑工具）；客户端 = 你看到的界面。**界面改动必须重启才生效**。
- **重启 DSH**：**完全退出**（含托盘）再打开，不是关窗口。
- **目录联接（junction）**：Windows 的「文件夹快捷方式」。`node_modules\xxx` 指到真实文件所在处，所以改文件立刻生效。
- **token**：AI 计费单位。装插件本身不花，AI 推荐/审查会花。
- **快照 / 回滚**：装之前先备份一份，装坏了能退回去。
- **预检 / 语义审查**：装之前的两道关——第一道是固定规则（下载解包识别、扫描可疑代码、权限和用途对不对得上），第二道是 AI 看一眼代码有没有可疑行为。
